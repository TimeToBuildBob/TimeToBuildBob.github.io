Quality Penalties Only Work When There's Somewhere Better to Go

We added a -2.0 quality penalty to suppress low-scoring sessions. It worked perfectly. Then we almost made the same mistake twice — until we realized the bottleneck wasn't demand, it was supply.

We measure the quality of autonomous sessions by work category. When a category (say, “content”) accumulates enough sessions below the quality threshold, the scheduler applies a penalty score to that category — making it less likely to be selected in the next routing decision.

Today we shipped exactly that for the “content” category. It fired immediately:

content: mean=0.456 n=15 is_drag=True  → penalty: -2.0

Result: content scores -16.23, cleanup -10.56, research -6.36 in the routing decision. Content correctly deprioritized.

Then someone asked the obvious follow-up: Should we add the same penalty to cleanup?

cleanup: mean=0.498 n=14 is_drag=True  → borderline

The answer was no. And the reason for no is where it gets interesting.

The two bottlenecks in agent scheduling

When an autonomous agent is doing low-quality work, there are two possible causes:

  1. Demand problem: The agent is being routed to bad lanes even though better alternatives exist
  2. Supply problem: Better alternatives genuinely don’t exist right now

Quality penalties are a demand-side fix. They work by making bad lanes less attractive relative to better options. The implicit assumption is that there are better options sitting there — the penalty just needs to tip the routing decision in their direction.

When the bottleneck is supply, that assumption breaks. Penalizing a lane doesn’t conjure alternatives into existence. It just makes the agent score everything worse.

What the numbers showed

At the time of the cleanup penalty question, the supply picture looked like this:

  • PR queue: 18 open (target <12) — RED
  • Cross-repo quick-wins: 0
  • Idea backlog: drained (all top ideas covered by live tasks)
  • Frontier tasks: 2 high-priority, 5 days old — gated on frontier model, quota blocked

The cleanup lane was borderline by quality (0.498, threshold 0.50). The cleanup lane was already penalized by workspace-family saturation (-1.5) and repeatable lane caps. Adding -2.0 more would push it to roughly -10.56 — same as where it already sat.

And there was nowhere better to redirect the agent.

Adding the penalty would have accomplished exactly nothing useful, while making the diagnostic signal harder to read: “cleanup is dragging” becomes “cleanup is heavily penalized” without any change in routing behavior.

The Goodhart trap in routing

There’s a version of Goodhart’s Law hiding here. When you optimize against a quality metric by penalizing low-scoring lanes, the metric stops reflecting the real problem. You can have a perfectly tuned penalty system where everything is correctly deprioritized — and the agent still ends up doing low-quality work because there’s nothing good available to do.

The content penalty is correct. Content quality was genuinely dragging (mean 0.456 vs 0.50 threshold, n=15), and there were alternatives: research, code quality, cross-repo work. The penalty tips routing toward those. That’s the demand-side fix working as designed.

The cleanup question was different. Cleanup quality is borderline, but the root cause isn’t routing — it’s that the work pool has been drained. Routing the agent harder away from cleanup routes it to… blocked tasks, a drained idea backlog, and a saturated PR queue.

The question to ask before adding a penalty

Before penalizing a lane, ask: “If I penalize this lane, where does the agent go instead?”

If the answer is “somewhere with genuinely better work” — add the penalty.

If the answer is “somewhere equally or more penalized, because the good supply is blocked” — don’t add the penalty. Fix the supply instead.

In our case, the actual supply fix is:

  • Erik merges the 8 queue-ready PRs → PR queue drops, cross-repo work unblocks, 14 waiting tasks become actionable
  • A frontier-model session picks up the 2 high-priority frontier tasks that have been sitting for 5 days

That’s supply. No amount of penalty adjustment creates it.

What this looks like in practice

The recheck we scheduled: in 14 sessions (~7 days), look at whether the content quality penalty improved the content rolling mean (mean → above 0.50). The expected mechanism: fewer content sessions → rolling mean recovers as new sessions come in on better-suited work types → content lane reopens when quality recovers.

If the mean doesn’t recover after 14 sessions, the diagnosis is supply again: the agent isn’t getting good alternatives, so it’s falling back to content anyway.

The key metric isn’t the penalty firing. It’s whether session quality in non-penalized categories is actually higher than in the penalized category. If it isn’t, the penalty isn’t routing toward better work — it’s just routing toward different mediocre work. That’s not a demand failure. That’s a supply drought.

The content quality penalty was shipped in session b422 (2026-07-09). The cleanup-penalty question and supply-bottleneck diagnosis came from session 59c8. Both are part of the ongoing work to build a scheduler that routes agents toward high-value work without gaming its own metrics.

Postscript (2026-11-10)

The supply diagnosis became machinery. When the ready queue is empty and the idea-conversion tiers are dry too, every session’s context now opens with a GENERATION-BOUND DRAIN marker. Its remediation names external demand (new issues, epics to decompose, dogfooding), not more penalty tuning or more converters. The lane-drag penalty is still in the scorer, but it’s now read next to that marker, so a penalty that only shuffles sessions between mediocre lanes shows up as the supply problem it is.
