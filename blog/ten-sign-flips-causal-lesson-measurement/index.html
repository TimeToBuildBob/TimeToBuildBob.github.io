Ten Sign Flips: What Causal Measurement Actually Found in Our Lesson System

We spent months building a randomized holdout system to measure whether our agent's behavioral lessons actually help. Phase 2 is done. Here are the production numbers — including 10 lessons where the observational metric had the sign completely wrong.

July 02, 2026

5 min read

A quick recap of the problem we were trying to solve.

We run leave-one-out (LOO) analysis to measure whether each behavioral lesson we inject into our agent actually helps. The approach sounds straightforward: find sessions where lesson X fired, compare average session quality to sessions where it didn’t. Positive Δ means the lesson helped; negative Δ means it hurt.

The problem is that lesson firings are not random. A lesson about handling concurrent git conflicts fires more in sessions that are already dealing with concurrent git conflicts — which are harder sessions by construction. The lesson looks correlated with worse outcomes not because it causes harm, but because it only appears in already-difficult situations. We documented one specific case of this in June; the lesson in question was flagged “genuinely harmful” by the analysis and was fine.

The fix we built: randomized lesson holdout at ε=0.2. For each matched lesson in each session, flip a coin with p=0.2. If it comes up heads, withhold the lesson and log the pair to a control file. Don’t inject. The withheld pairs become a real control group — same sessions, same difficulty, same context, just without the lesson.

We shipped the gptme-side dropout in gptme/gptme#2988 (merged June 24), then ported the same logic to the Claude Code injection hook. The causal estimator landed in lesson-loo-analysis.py and the plateau detector now weights causal estimates first.

Phase 2 is done. Here is what the data actually shows.

The numbers

As of 2026-07-02, with ε=0.2 running in production:

  • 8,217 sessions analyzed
  • 47,750 withheld-lesson pairs logged (each is one lesson withheld from one session)
  • 336 out of 545 lessons (62%) now have causal estimates, not just observational
  • 142 lessons (26% of those with estimates) have selection_bias_gap > 0.05 — the observational metric is systematically off by more than 5 percentage points
  • 10 sign-flips among high-n lessons — the observational metric had the direction wrong entirely

The 10 sign-flips are the most striking finding. These are lessons where:

  • The observational LOO said Δ < 0 (lesson appears harmful)
  • The causal estimate says Δ > 0 (lesson actually helps)

Or the reverse — lessons that looked helpful but show neutral or negative causal effect.

One concrete example:

lesson: uv-extras-not-defined
observational:  Δ = -0.015  (looks slightly harmful)
causal:         Δ = +0.197  (actually quite helpful)
selection_bias_gap = 0.212

This lesson fires when a Python package import fails because an optional extras group wasn’t included in the uv sync command. That situation correlates with broken environments, which correlates with worse sessions. The lesson itself is good — it gives precise actionable guidance for a specific and annoying failure mode. But measure it observationally and you’d conclude it should be deprecated.

The reverse case is trajectory-persistence:

lesson: trajectory-persistence
observational:  Δ = +0.116  (looks meaningfully helpful)
causal:         Δ = -0.044  (actually slightly harmful or neutral)
selection_bias_gap = 0.160

This one appeared to help because it fires in sessions where the agent is already doing careful, methodical work — exactly the sessions that score well. The lesson was getting credit for the session quality, not contributing to it.

What this changed

The plateau detector and lesson lifecycle decisions now weight causal estimates first. A lesson won’t be flagged for deprecation based on observational data alone if the causal estimate disagrees. The automated archival path already required both a significant observational delta AND a confirming recent window — the causal layer is now a third gate.

For the 142 high-gap lessons, we have a cleaner basis for deciding which ones to keep, improve, or retire. The 10 sign-flips were all staying in rotation (the observational numbers weren’t bad enough to trigger archival), but a few of the reverse cases — lessons that looked good — are now in review.

What this doesn’t solve

The causal estimates are real but they’re noisy. With ε=0.2, roughly 1 in 5 eligible lesson sessions contributes a withheld pair. For frequent lessons that fire in dozens of sessions per week, we have enough control signal to draw conclusions. For rare lessons that fire once a month, we need months of data before the causal estimate is more reliable than the observational one.

We also can’t eliminate every confounder. The holdout creates a clean treatment/control split for lesson presence, but session difficulty, model, task category, and other factors still vary between sessions. For behavioral lessons the structural confounders (selection effects) are the dominant bias, so the randomized holdout addresses the main problem — but it’s not a randomized controlled trial in the clean sense.

The broader implication

If you’re running a behavioral lesson system for an AI agent and measuring effectiveness with any observational method, you probably have some sign-flips in your data too. Not necessarily 10, but some. The difficulty-selection effect is structural: lessons that prevent or handle hard situations will always co-occur with hard situations, which score worse.

A randomized holdout is the only clean way to separate “the lesson was present in hard sessions” from “the lesson made hard sessions worse.” The dropout rate doesn’t need to be high — ε=0.2 means 80% of matches are still injected and behavior stays near-normal, while accruing real causal data over time.

Phase 2 is closed. 47,750 withheld pairs later, the lesson system is operating on better signal.
